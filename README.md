# 星露谷物语 · 攻略站

一个纯静态的游戏攻略前端页面，**像素风游戏界面质感**（木框 + 羊皮纸 + 物品栏格子），包含 17 大模块，图标全部使用游戏内真实贴图：

🌾 农作物 · 🍄 收集物 · 🎣 钓鱼 · ⛏️ 采矿 · ⚔️ 战斗 · 📜 任务 · 👤 NPC · 🎉 节日 · ✨ 事件 · 📦 收集包 · 🏺 古物 · 🧀 工匠制品 · 🔨 打造 · 🍳 料理 · 🌱 种子 · 🍎 果树 · 🌲 树木 · 🌲 树木

## 核心功能

- **游戏化视觉**：导航与模块标题使用游戏内真实贴图（emoji 仅作贴图缺失时的兜底）；木框 + 羊皮纸 + 物品栏格子质感；导航栏木板纹理、选中态做成游戏标签页
- **兜底图只在贴图真的加载失败时才出现**：官方贴图是带透明通道的，兜底若常驻在下层就会从每个透明像素透出来（实测平均 48.5% 的格子面积会被污染）。现在由 `onerror` 驱动——容器带 `.has-img` 时兜底默认收起，加载失败才打上 `.icon-failed` 展开；纯 emoji 图标不受影响
- **像素级清晰的图标**：物品贴图 48×48 按 **1:1** 呈现、NPC 立绘 128×128 按 **1/2** 呈现（64px）——两者都是**整数倍率**，避免非整数缩放导致的像素错位
- **社区中心收集包（含进度勾选）**：31 个收集包按 7 个房间分组，逐格勾选已捐赠的物品，进度存 `localStorage`（刷新不丢、可一键清空）；支持「任选 N 个」型收集包（物品数多于槽位时只需交够 N 格）；金额包标明所需金币
- **古物与博物馆捐赠**：**41 件古物**含获取途径与售价，逐件勾选捐赠进度（`localStorage`）；顶部汇总**博物馆总进度**（古物 + 矿物的可捐赠总数）并标出**奖励门槛**（40 件解锁矮人语 / 41 件得古代种子配方 / 60 件下水道钥匙 / 95 件生锈钥匙）
- **工匠制品（26 项）**：按 **11 类产出机器**（蜂房 / 小桶 / 木桶 / 罐头瓶 / 烘干机 / 熏鱼机 / 压酪机 / 蛋黄酱机 / 产油机 / 织布机 / 神秘树）分组；**变价品写明计价规则**（果酒 = 3 × 原料价值、果干 = 7.5 × 原料价值 + 25…）；产出机器可点进打造配方
- **打造（138 个配方）**：按 16 个分类（炸弹/围栏/洒水器/工匠设备/肥料/装饰/钓鱼/戒指/食物/消耗品/照明/精炼/家具/存储/标牌/杂项）组织；显示所需材料、每次产出数量、售价与**配方获取方式**（技能等级 / 商店购买 / 初始拥有）；材料 chip 可跳转到对应条目，物品详情页也能反查「用于打造」
- **料理（81 道）**：原料、售价、回复体力、食用增益与持续时长、菜谱获取方式；可按售价 / 回复体力 / 原料数排序，按有无增益筛选；**原料 chip 可跳转到对应条目**（作物/鱼/矿…），物品详情页也能反查「用于料理」
- **种子（69 项）**：中文 Wiki `Category:种子` 全集（70 项，排除「咖啡豆」——同一物品已由农作物收录）。含售价 / 购买价 / 成熟时间 / 季节 / 获取方式（商店价、绿洲、姜岛商人、打造、掉落…）；**成熟时间不定的（松果 / 草籽…）保留原文「不定 / 立即」**而不是编一个天数；售价 0 显示为「不可出售」
- **种子 ↔ 农作物 / 收集物 / 果树 / 树木双向打通**：种子卡片与详情里的「成熟后得到」可点进对应条目（防风草种子 → 防风草、春季种子 → 野山葵、苹果树苗 → 苹果树、松果 → 松树）；反过来，这些模块的详情页有「**由这些种子种出**」一节。**65 项结果物可直接跳转**，缺口表只剩「草」一项（农场杂物，不属任何模块）
- **果树（8 棵）**：苹果 / 杏子 / 樱桃 / 橙子 / 桃子 / 石榴 / 香蕉 / 芒果。含结果季节、成熟周期（28 天）、果实售价与回复体力、树苗售价；详情附**果树通用规则**（3×3 空地、冬季不死、果实累积 3 天、品质逐年提升、温室与姜岛全年结果）
- **树木（8 棵）**：松树 / 枫树 / 橡树 / 桃花心木树 / 神秘树 / 绿雨树 / 茶树 / 棕榈树。含种子、**树液采集器产物**（松焦油 / 枫糖浆 / 橡树树脂 / 树液 / 神秘糖浆）、成熟时间与砍伐产出；可按「能否安装采集器」筛选
- **名称别名机制**：同一件东西在站内有多个叫法时（如「苹果」↔「苹果树」），别名也能被搜索与跳转命中——**但别名不覆盖已有的正式名**（「芒果」已由农作物收录，果树模块就不登记该别名，R53）
- **收集包与物品双向打通**：收集包里的每个需求物品都能点开对应条目（作物/鱼/矿/怪…）；反过来，任意物品的详情页都有「用于收集包」一节，反查它被哪些包需要
- **礼物双向打通**：NPC 的最爱礼物 chip 可直接点开该物品；反过来，物品详情页有「送礼对象」一节，列出最爱它的村民——**49 个礼物可直接跳转**，其余属于尚未收录的模块，已在自检的缺口表中登记
- **农作物收益模型**：按 `（28 天季节内总收获额 − 种子价）÷ 末次收获日` 计算「每日净收益」，支持按 每日收益 / 成熟天数 / 售价 / 种子价 排序，用于横向比较作物效率（多季作物按单季估算，弹窗内附算法说明）
- **负收益警示**：种子价高于售价的作物（如向日葵，靠收获时掉落种子回本）以红色 `⚠️` 标注，避免把正确算法误读成 bug
- **17 模块详情弹窗全覆盖**：所有卡片可点击展开完整数据——农作物显示经济数据与算法、钓鱼显示出没条件与难度、NPC 显示生日与最爱礼物
- **掉落物交叉跳转**：怪物掉落物中能对应到条目的，可直接点击跳转到采矿 / 收集物对应条目
- **深链接可分享**：地址栏实时反映当前位置（`#fish/legend` 这样的 `#模块/条目`），刷新、收藏、发给队友都能直接落到同一条目；非法或过期的链接安全降级、不会白屏
- **状态记忆**：记住上次浏览的模块，回访不再总是跳回农作物
- **全局搜索**：跨 17 模块搜索并定位高亮，索引涵盖用途、掉落物、礼物、房间等字段（可「按用途找东西」）；**回车直达第一条结果**；跳转前自动清空目标模块筛选，避免目标条目被筛选条件挡住
- **多维筛选**：季节 / 水域 / 类型 / 房间筛选，标题实时显示「当前显示 N 条」
- **键盘可达**：卡片可 Tab 聚焦、Enter / 空格打开详情；弹窗关闭后焦点归还
- **左侧纵向侧栏导航**：17 个模块竖排在左侧，**可独立滚动**，每条带贴图 + 名称 + **条目数徽标**（横排没有空间放这个数字）。三档响应式：≥1121 完整侧栏 / ≤1120 收成图标条（名称与计数隐藏，靠 `title` 提示）/ ≤640 整行转纵向、导航自动变回顶部横向滚动条——**同一份 DOM，不维护两套结构**。当前模块始终自动滚入视野（横向滚 `scrollLeft`、纵向滚 `scrollTop`）
  - 为什么不再用横向标签栏：17 个模块横排要 ~1700px，**只有 ≥1920 的屏幕能一眼看全**，1600/1440/1366 都已溢出；而 `.page` 原来被 `max-width:1240px` 框住，1920 屏上两侧各有 340px 纯空白——侧栏正好用这块空间，**宽屏上卡片列数反而变多**

## 新增一个模块（改 1 处即可）

模块的全部能力都声明在 `js/main.js` 的 **`REGISTRY`** 注册表里（唯一事实来源）：

```js
{
  id: "bundles",                 // 模块 id（决定 #module-xxx / #xxxCount / #shown-xxx）
  label: "收集包", sub: "社区中心收集包的所需物品与奖励",
  sprite: "achievement", icon: "📦",     // 导航图标：真实贴图 + emoji 兜底
  spriteFor: "",                 // 条目贴图命名前缀（物品为 ""、NPC 为 "npc-"；不写 = emoji 呈现）
  data: "BUNDLES",               // 数据数组名（在 MODULE_DATA 中登记）
  render: renderBundles,         // 渲染函数
  stateKey: ["bundles"],         // 本模块用到的筛选状态键
  resetFilter: (s) => { s.bundles = "全部"; },   // 搜索跳转前重置筛选（R18）
  indexExtra: (b) => [b.reward],  // 搜索索引的附加关键词
  detail: (b) => ...,            // 详情弹窗渲染函数
}
```

**不需要**再改 `FILTER_RESET`、`DETAIL_RENDERERS`、`buildIndex()`，也不需要改 `test/check.js`——
计数、渲染冒烟、详情渲染、搜索索引覆盖、贴图齐备这些断言都会自动覆盖新模块。

## 开发流程（重要）

**改数据/代码 → 自检 → 双击 `scripts\deploy.bat` 上线**：

```bash
node test/check.js             # 1. 一键全量自检（16 节 228 处断言，必须通过）
                               #    ① JS 语法 ② 数据完整性（注册表自洽 / id 唯一 / 贴图覆盖）
                               #    ③ 渲染冒烟（17 模块计数与 section）
                               #    ④ 收益算法基准值 + 17 模块详情渲染（全 768 条）
                               #    ⑤ 点击→弹窗、交叉跳转的合成事件验证
                               #    ⑥ 收集包：勾选→存盘→读回→完成判定、任选包、悬空引用表
                               #    ⑦ 深链接：#模块/条目 解析与落地、前进后退、搜索回车、状态记忆
                               #    ⑧ 反向索引：礼物↔物品↔收集包互洽、缺口表、卡片 chip 点击优先级
                               #    ⑨ 打造：id 不冲突、分类筛选覆盖、材料反向索引与跳转
                               #    ⑩ 工匠制品：产出机器分组、变价品计价规则、机器跳打造
                               #    ⑪ 古物与博物馆：捐赠进度读写、清单无重名、奖励门槛合理
                               #    ⑫ 种子：id/名称不冲突、季节筛选覆盖、结果物落点守恒、反向索引
                               #    ⑬ 果树：树↔树苗跨模块交叉校验、别名不覆盖正式名、芒果让位
                               #    ⑭ 树木：树↔种子跨模块交叉校验、树液产物、野生树例外
                               #    ⑮ 侧栏导航：每个模块都有入口、条目数徽标、两种布局各自的滚动兜底
                               #        以及**几何一致性**（木板缝周期 == 条目高 + 间距、缝起点 == 条目高、标题不参与 flex 压缩、缝层背景 local）
                               #    ⑯ 模块图标贴图齐备 + 图标兜底时机 + 搜索索引覆盖 + 无临时文件残留
                               #    （①~⑯ 的逐模块断言由注册表驱动，新增模块自动纳入）
node test/scroll-shot.js <url> measure   # 布局/滚动类改动：量侧栏几何（是否对齐、是否露白）
node test/scroll-shot.js <url> <out.png> 1440 900 bottom   # 滚到页面最底再截图
node test/verify-wiki.js       # 2. 新增数据时：存在性核对（双轮，防编造/错名）
                               #    ① 中文名直查中文 Wiki（全量条目）
                               #    ② 英文名交叉验证（英文页名规范）
node test/audit-completeness.js # 3. 成批补内容后：完备性审计（防遗漏）
                               #    对照中文 Wiki 分类全集做双向差集
# 4. 双击 scripts\deploy.bat（自动：版本号+1 → 自检 → 下载贴图 → 提交推送 → Actions 部署）
```

> 所有历史问题和规避规则见 **`docs/PROBLEMS.md`**，改动前务必查看。

## 技术栈

纯 **HTML + CSS + JavaScript**，无框架、无构建步骤、无后端依赖，所有资源使用相对路径，可直接部署到任意静态托管平台。

## 本地预览

方式一：直接双击 `index.html`。

方式二：在项目目录运行

```bash
python -m http.server 8000
```

然后浏览器访问 <http://127.0.0.1:8000>。

## 部署到 GitHub Pages

### 方式 A：网页上传（最简单）

1. 新建一个 GitHub 仓库（例如命名为 `stardew-guide`，选 **Public**）。
2. 进入仓库，点击 **Add file → Upload files**，把本项目里的 `index.html`、`css/`、`js/` 以及 `.nojekyll` 全部拖进去，提交。
3. 打开仓库 **Settings → Pages**：
   - **Source** 选择 `Deploy from a branch`
   - **Branch** 选择 `main`，目录选择 `/ (root)`，保存
4. 等待几分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可。

### 方式 B：命令行部署

项目已初始化 git 仓库，执行：

```bash
git init                        # 若尚未初始化
git add .
git commit -m "init: 星露谷物语攻略站"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

推送成功后，按方式 A 的第 3 步在 Settings → Pages 里开启 Pages 即可。

| 模块 | 数据数组 | 模块 | 数据数组 |
|---|---|---|---|
| 农作物 | `CROPS` | 收集包 | `BUNDLES` |
| 收集物 | `COLLECTIBLES` | 古物 | `ARTIFACTS` |
| 钓鱼 | `FISH` | 工匠制品 | `ARTISAN` |
| 采矿 | `MINERALS` | 打造 | `CRAFTING` |
| 战斗 | `MONSTERS` | 料理 | `COOKING` |
| 任务 | `QUESTS` | 节日 | `FESTIVALS` |
| NPC | `NPCS` | 事件 | `EVENTS` |
| 种子 | `SEEDS` | 果树 | `FRUIT_TREES` |

直接修改或新增条目，刷新页面即可生效，无需改动其他文件；要让新模块获得全部既有能力（详情弹窗 / 搜索 / 深链接 / 反向索引），才需要在 `js/main.js` 的 `REGISTRY` 里登记。
