# 开发问题记录与规避清单

> 本文档汇总本项目开发过程中遇到过的所有问题、根因与解决方案，
> 并沉淀为后续开发的强制性规避规则。**每次改动前先看「规避规则」。**

---

## 一、问题汇总

### 1. 脚本与部署

| # | 问题现象 | 根因 | 解决方案 |
|---|---------|------|---------|
| 1 | 双击 `deploy.bat` 窗口一闪就关 | `$ErrorActionPreference = "Stop"` 下，原生命令（`gh auth status`）向 stderr 输出即触发致命错误，脚本在开头就退出；且 `.bat` 末尾无 `pause` 兜底 | 错误策略改 `Continue`，用 `$LASTEXITCODE` 判断；`.bat` 末尾加 `pause`；`Fail()` 显式退出 |
| 2 | `git push` 报 `couldn't create signal pipe, Win32 error 5` | 受限环境限制 Git for Windows 的 MSYS 运行库创建信号管道（非项目问题） | 在正常终端执行 push；SSH 密钥已验证有效 |
| 3 | 提交作者是占位身份 `game-guide@local` | 本地无 git 身份配置 | 部署脚本用 `gh api user` 取真实账号，自动 `git commit --amend --reset-author` |
| 4 | `.ps1` 中文乱码 / 解析报错 | 文件为 UTF-8 无 BOM，Windows PowerShell 5.1 按 ANSI 读取导致乱码和花括号误判 | 所有 `.ps1` 保存为 **UTF-8 带 BOM**；**每次编辑后必须重加 BOM 并校验** |

### 6. 数据正确性（最值得警惕的一类）

### 7. 功能实现（第二轮优化发现）

| # | 问题现象 | 根因 | 解决方案 |
|---|---------|------|---------|
| 18 | 水稻收益算出 `NaN` | `data.js` 中 `rice.growth` 是字符串 `"6-8"`（水稻近水可提前 2 天成熟），算术运算 `28 - "6-8"` 得 `NaN`，NaN 会沿着排序比较器污染整个列表顺序 | 新增 `cropGrowthDays()` 容错解析：数字直接用，区间取**上限**（偏保守）；显示仍保留原文 `"6-8 天"`，不丢失信息 |
| 19 | **霜瓜永远无法通过筛选触达** | 农作物筛选栏硬编码 `春/夏/秋`，而数据里已有 3 种含冬季的作物（霜瓜、茶叶、齐瓜） | 抽出 `CROP_SEASON_FILTERS` 常量并补「冬」；新增断言「数据中出现过的季节必须有对应筛选按钮」，杜绝同类漏配 |
| 20 | 搜索跳转"跳了个空"：搜到的条目没被高亮 | `focusItem()` 只切换模块，不清空该模块**已有的筛选条件**——在「海洋」筛选下搜河流鱼，卡片根本不在 DOM 里 | 抽 `FILTER_RESET` 映射，跳转前先重置该模块筛选并重渲染 |
| 21 | 筛选后标题仍写「共 46 条」，用户以为筛选失效 | `setCount()` 传的是**全量长度**而非筛选结果数 | 新增 `setShown()` 输出「当前显示 N 条」，与总数并列显示；`#xxxCount` 保持总数不变，兼容既有断言 |
| 22 | **3 张贴图（cave-grub / gold-slime / iridium-slime）反复重跑下载脚本也补不上** | `download-images.ps1:337` 的兜底映射 `$pageNames` 只在 `$items[$e.Key]` 存在时才会被查询，而这 3 个 id **只写在 `$pageNames` 里、从未进入主下载列表 `$items`** → 该兜底分支对它们是**死代码**，永远不触发。脚本报「失败 0 个」是因为压根没尝试 | 待修：把 3 个 id 按真实 Wiki 文件名补进 `$items`（依 R12 先验证存在性）。当前用自绘 SVG 兜底图标，不影响使用 |
| 23 | 部署脚本在沙箱受限模式下**完全跑不通**：`index.html`/`.git` 写入被拒、`ssh` 报 `couldn't create signal pipe, Win32 error 5` | 两道**互相独立**的墙：①沙箱对 `.git` 等路径的写入拦截；②受限模式下进程无法创建命名管道，而 Git for Windows 的 MSYS 运行库需要它。**这不是项目缺陷** | 对本机部署命令做**一次性提权**（full access）后一次通过：bump 版本、自检、贴图下载、提交、推送全部成功，Actions 26s 完成。见 R20 |
| 24 | R15 的判断有偏差：以为 PowerShell 连不上 Wiki 是 schannel 限制 | 实为**沙箱拦截**。完全权限下 `download-images.ps1` 原样跑通（220 项全部命中、失败 0） | 已修正 R15：脚本本身没问题，缺的是权限 |

### 9. 内容完备性（第四轮审计发现）

> 结论：**存在性可靠，完备性不足**。9 个模块里 3 个已完整、4 个有小缺口，但另有 **10 个整块游戏系统完全没有覆盖**。

| # | 问题现象 | 根因 | 解决方案 |
|---|---------|------|---------|
| 30 | **存在性审计自身有覆盖盲区**：声称"全部条目已核对"，实际只覆盖 231/313 条（73.8%），82 条从未验证过 | ①`verify-wiki.js` 依赖手工维护的英文映射表 `EN`，数据里新增的中文条目常忘记补映射，脚本只打印一行 ⚠️ 就跳过；②QUESTS(10) 与 EVENTS(12) **完全没纳入映射表与审计范围** | 改为**双轮核对**：第一轮用中文名直查中文 Wiki（无需映射表，覆盖全量 313 条，实测 89.5% 命中）；第二轮保留英文交叉验证。新增数据自动进入审计，不再依赖人工补表 |
| 31 | **从没有过完备性审计**：工具只回答"我们收录的是否真实"，从不回答"游戏里有的我们是否漏收" | `verify-wiki.js` 是单向的（data → wiki），缺少反方向（wiki → data）的差集能力；且从未有人把 Wiki 分类全集拉下来比对 | 新增 `test/audit-completeness.js`：拉取中文 Wiki 分类全集做双向差集。首轮实测 —— 逐模块缺 **59 项**（收集物 10 / 采矿 24 / 战斗 14 / NPC 10 / 农作物 1），另有 **10 个整块系统**未覆盖：烹饪 82、打造 90、工匠制品 35、果树 9、动物 13、武器 69、种子 70、古物 43、建筑 57、工具 24 |
| 32 | 审计时先用**英文** Wiki 分类做比对，结果 `Category:Crops` 只返回 5 项 | 星露谷 Wiki 的英文分类是`Category:Crops`这种"容器类"，真实内容散在 `Spring crops`/`Vegetables` 等子类；中文 Wiki 反而是干净的**中心类**（`农作物`按季节分、`鱼`、`怪物`、`NPC` 都是直接成员） | 完备性比对统一以**中文 Wiki 分类**为准；并注意排除同名分类页（`鱼`、`怪物`、`矿石`这类既是分类又是条目） |
| 33 | 首次统计"无英文映射"得出 139 条，实际只有 60 条 | 统计脚本的正则 `([a-z0-9-]+)\s*:\s*"` 无法匹配**带引号的键**（`"blue-jazz": "Blue Jazz"`，键后先有引号再有冒号），把 79 个带连字符的键全部漏掉了 | **统计脚本本身也要被验证**：数字异常时先怀疑统计口径。改用直接按 `EN[mod][id]` 查表，由数据侧驱动计数 |

| # | 问题现象 | 根因 | 解决方案 |

| 35 | `cave-grub`（蛆）英文页名错误，且数值全错（HP 25/伤害 6/矿井 1-39 层） | 真实怪物叫 **`Grub`**，信息框权威值为 **HP 20 / 伤害 4 / 矿井 15-29 层**、掉落含虫肉 60%/古代种子 0.5%/白色藻类 2%/稻芽 10% | id 正名为 `grub`，数值与掉落按 Wiki 信息框修正 |

### 12. 架构重构（第六轮：模块注册表）

> 起因：9 个模块全部**按物品类型**切分，站内已有 50 条「采集包」引用无处可去。要加第 10 个模块（社区中心收集包）时发现——「一个模块」被写死在 5 处，加模块必漏配。

| # | 问题现象 | 根因 | 解决方案 |
|---|---------|------|---------|
| 39 | 删改 `js/main.js` 的一整段（137 行）时，**DSH 文件工具无法按行区间删除**，而 PowerShell / Python 写该项目目录一律 `PermissionError` | 双重限制叠加：①`edit` 是字面量替换工具，删 137 行需要把全文抄进 `old_string`，不可靠；②项目在会话工作区（`D:\deepseek`）**之外**，沙箱禁止派生进程写入，且该拦截来自**沙箱策略而非 ACL**（#26 已证） | 对**那一条精确命令**做一次性提权（`danger-full-access`）执行「脚本放工作区内、只写项目文件」的行区间拼接，之后照常回归自检。**判据**：`[sandbox: file access denied under workspace-write mode]` + 提示 `escalation available` 即为此情形，不要反复换写法硬试 |

### 14. 深链接与状态记忆（第八轮：P1）

> 起因：攻略站的主要用法是「搜到某条目 → 把链接发给队友」，而此前 `focusItem()` 能定位高亮却**不写 URL**——刷新回首页、后退失效、链接无法分享。本轮把该函数并入统一的 `gotoItem()`（重置筛选 → 切模块 → 高亮 → 写 URL）。

| # | 问题现象 | 根因 | 解决方案 |
|---|---------|------|---------|
| 47 | 加 hash 路由时容易踩两个反向的坑：①每次点击都 `pushState` → 后退键要按几十次才退得出去；②模块切换自己也 `replaceState` → 浏览器后退**永远回不到上一个模块** | 两个坑源于同一个设计缺失：**没有区分"用户发起的导航"与"代码顺带同步 URL"** | 定死两条：①**模块切换一律 `replaceState`**（就地改写），②**只有「打开条目详情」`pushState`**（可回退的最小粒度）。③程序化写 hash 时置 `routerGuard`，避免自己触发的 `hashchange` 再跑一遍造成重复跳转 |
| 48 | 同模块内切换条目时，用户已选的筛选条件被清空 | 深链接落地复用了「跳转前重置筛选」（R18）——那条规则是为**跨模块**跳转写的：目标可能在当前筛选之外。同一模块内条目本来就可见，再重置反而把用户的上下文抹掉 | 只在**模块发生变化**时重置筛选：`if (moduleId !== currentModuleId()) resetModuleFilter(moduleId)`。**规则要连它的适用边界一起记**，否则会被过度套用（R18 的正确范围是"跨模块跳转"） |

## 二、规避规则（后续开发必须遵守）

| 编号 | 规则 |
|------|------|
| R1 | **模板 id 与查询 id 必须一致**：写完渲染函数后，grep 核对 `${m.id}Count` 与所有 `#xxxCount` 引用 |
| R2 | **DOM 查询一律空值安全**：可能为 null 的元素用 `if (el)` 或 `setCount()` 模式，绝不裸调 `.textContent` |
| R3 | **每次发布 bump 版本号**：`index.html` 的 `?v=N` 必须 +1，否则浏览器缓存会出幺蛾子 |
| R4 | **发布前必须跑冒烟测试**：`node test/smoke.js`（已集成进 `deploy.bat`，失败自动中止部署） |
| R5 | **改过任何 `.ps1` 后必须重加 UTF-8 BOM** 并用解析器校验语法。注意：**通用文本编辑工具会静默剥离 BOM**（#37），所以每次编辑后都要重新校验，不能假设它还在。最快诊断：按 UTF-8 显式读入再 `ParseInput`，通过即说明是编码问题而非语法问题 |
| R6 | **批量外部 API 调用前查平台限制**（如 MediaWiki `titles` ≤ 50/次），超限必须分批 |
| R7 | **对接外部 API 先确认返回格式的规范化行为**（大小写、空格/下划线、转义） |
| R8 | **部署后验证线上**：核对线上文件与本地一致、资源 200、渲染无报错（用 `test/verify-online.js` 思路，或 Node fetch 抽查） |
| R9 | **GitHub 基础设施错误先重试**（429 / 构建失败），不要急着重构代码 |
| R10 | **复杂脚本写文件执行**，避免内联命令被 shell 转义破坏；jq 表达式保持纯 ASCII |
| R11 | **数据字段先定义后使用**：给数据加新字段（如 `locCat`）时，确保所有渲染/筛选逻辑同步更新，并跑数据完整性校验（id 唯一、必填字段齐全） |
| R12 | **新增数据必须验证存在性**：任何新物品/怪物/NPC，先用 Wiki 搜索/`allpages` API 确认条目真实存在，杜绝凭记忆编造（已因此误收录 4 个不存在的条目） |
| R13 | **文件名不手工猜**：贴图/图片一律用 `pageimages` API 按英文条目名取真实 URL（如 Tigerseye、Star Shards），不按 `ItemName.png` 惯例脑补 |
| R14 | **持续失败先怀疑数据**：某条目反复下载失败，第一反应查"它是否真的存在于游戏/Wiki"，而不是反复改文件名映射 |
| R15 | **能用 Node fetch 直连外部源就自己做**：受限模式下 Node fetch（undici/OpenSSL）可访问星露谷 Wiki，而 PowerShell 的 `Invoke-RestMethod`/`Invoke-WebRequest` 报「基础连接已经关闭」——**该限制来自沙箱，而非 schannel**（#24 已证伪原判断：完全权限下 `download-images.ps1` 原样跑通、220 项全部命中）。用 Node 脚本下载与验证可减少对权限的依赖 |
| R16 | **参与算术的字段必须是数字**：数据里混入 `"6-8"` 这类区间字符串会让 `NaN` 沿排序/聚合静默扩散（排序结果整体失效却不报错）。进入计算前一律经容错解析函数转换，区间取保守端 |
| R17 | **新增数据分类必须同步补筛选入口**：数据中出现新季节/新水域/新类型时，筛选常量必须同步扩充，否则内容「存在但不可达」；`check.js` 已加断言自动拦截 |
| R18 | **跳转前先清空目标模块的筛选**：任何「从 A 跳到 B 条目」的路径都要先重置 B 的筛选并重渲染，否则目标条目可能被筛选条件挡在 DOM 之外，高亮落空 |
| R19 | **能进程内验证就不要依赖外部浏览器**：本沙箱中 Chrome/Edge 无头模式因 mojo 需要命名管道而无法启动（`platform_channel.cc: Check failed`），视觉验证需用户人工确认；**交互逻辑应在 `check.js` 内用合成事件直接驱动真实处理器**（见第 5 节），不依赖浏览器 |
| R20 | **本机跑 `deploy.bat` 需要完全权限**：沙箱受限模式下 `.git` 写入与 `ssh` 命名管道两道墙都过不去（#23），表现为「版本号没变、没有任何提交、推送失败」。这**不是脚本缺陷**，别去改脚本；用一次性提权执行，或由用户在普通终端双击 `deploy.bat`。另注：每次失败都是**空操作**（不产生半成品提交），可放心重试 |
| R21 | **临时文件必须清理，且要有断言兜底**：`deploy.bat` 会 `git add -A`，根目录遗留的预览/调试文件会被一起提交上线。临时文件一律用 `_` 前缀命名，`check.js` 已加断言「根目录无 `_` 开头文件」，自检失败会直接中止部署（本轮已实测拦住一次） |
| R22 | **视觉改动先截图再发布**：界面类改动不能只靠审阅代码。截图时必须在预览页禁用 CSS 动画，否则 `--virtual-time-budget` 截到淡入中途，会把正常样式误判为失效 |
| R23 | **图标尺寸取源图的整数倍或整数分之一**：48px 贴图按 1:1、128px 立绘按 1/2 呈现，避免非整数缩放造成像素错位。这条对像素画清晰度的影响**大于** `image-rendering` 属性本身 |
| R24 | **正确的算法也要检查呈现**：算出负数、极值、0 这类"对但反直觉"的结果时，必须给出视觉区分或成因说明，否则用户会当成 bug（向日葵负收益即此例） |
| R25 | **存在性审计必须以「无需人工维护映射」的方式覆盖全量**：任何依赖手工映射表的核对，都会随数据增长而静默失守（#30 的 82 条盲区就是这么来的）。本项目统一用**中文名直查中文 Wiki**，新增数据自动纳入 |
| R26 | **定期跑完备性审计**：`verify-wiki.js` 只防编造，防不了遗漏。每次成批补内容后跑 `node test/audit-completeness.js`，对照 Wiki 分类全集看差集（#31） |
| R27 | **对外的比对口径先验证再下结论**：分类型数据在 Wiki 上的组织方式各家不同（英文是容器类、中文是中心类），拿错口径会得出"Wiki 只有 5 种作物"这种荒谬结论（#32） |
| R28 | **统计脚本的数字先自证再用**：算出的指标异常时（如"139 条无映射"），第一反应是查统计口径而非直接写进结论（#33） |
| R29 | **判伪要看三处，判真只需一处**：某条目若在①Wiki 汇总页、②权威分类名录、③图片文件三处**全部查不到**，基本可断定是编造（#34 的铱史莱姆即三缺）。反之，**"分类名录里没有"绝不等于编造**——史莱姆/蝙蝠变体、任务、心事件都挂在 `Slimes`/`Bats`/`任务`/`随机事件` 汇总页下，属正常情况，误判会把真内容删掉 |
| R30 | **Actions 报「找不到 github-pages artifact」时先查证再动手**：用 `gh api repos/<owner>/<repo>/actions/runs/<run-id>/artifacts` 确认 artifact 是否真的存在。**若存在即为竞态**（#38 实测 213982 字节确实已生成），用 `gh workflow run pages.yml --ref main` 重新触发即可，**不要改 workflow、不要删重建仓库** |
| R31 | **补完内容后必须跑完备性审计并做到"可解释归零"**：目标不是"数字为 0"，而是**每一项剩余差异都有明确记录的理由**。经核对的排除项写进 `audit-completeness.js` 的 `EXCLUDED` 表（含原因），否则每次审计都会把同一批无关项当成缺口重复排查 |
| R32 | **移动脚本前先把内部路径改好，再整体搬移**：不要"边移动边修改"，否则出错时分不清是路径问题还是改动问题。搬移后必须校验三件事——①`.ps1` 仍是 UTF-8 带 BOM（R5）②语法解析通过 ③根目录推算正确。`.bat` 中 `%~dp0` 会随文件移动而改变，工作目录需显式回退到项目根 |
| R33 | **行区间级的文件手术用「脚本 + 一次性提权」**：DSH 的 `edit` 是字面量替换工具，删除上百行需要把全文抄进 `old_string`，既脆弱又易错；而项目目录在会话工作区之外时，派生进程写入会被沙箱拒绝（#39）。此时对**那一条精确命令**提权执行（脚本放工作区内、只写目标文件），随后立刻回归 `node test/check.js` 验证。看到 `escalation available` 提示就是这个情形，别反复换写法硬试 |
| R34 | **配置表里判别「有没有」要用判存，不能用判真**：`spriteFor: ""` 是合法取值（表示贴图无前缀）却是 falsy，`if (!sec.spriteFor)` 会把所有物品模块误判成"无贴图"（#41 实测把覆盖率错报成 48/48）。空串、`0`、`NaN` 这类**合法的假值**在配置中一律用 `hasOwnProperty` / `!== undefined` 判断 |
| R35 | **改统计口径前先确认原口径的语义边界**：把「模块清单」改成数据驱动时，顺手把所有模块都算进贴图分母，覆盖率立刻从 331/332 变成 331/366，凭空多出 34 个"缺口"（#40）。**更通用的写法未必是更正确的口径**——重构统计类代码时，先问「原来这张报表到底想覆盖谁」 |
| R36 | **对接外部数据源先找「权威机制」，别猜存储约定**：查中文 Wiki 物品中文名连试四条路（英文标题直查、中文页 langlink、英文页 langlink、全文搜索）覆盖率分别只有 0% / 25% / 27% / 0%——因为该 Wiki 的名表根本不在页面标题上，而在 `Module:Items` 里用 **item id 串联**（#42）。**判据**：某种查法大面积"查不到"时，先怀疑**数据组织方式**假设错误，而不是继续换查询词 |
| R37 | **「有多少选项」与「要选几个」必须分成两个量**：收集包的物品数与所需格数在「任选型」里不相等，混用一个 `slots` 会让 `filled >= slots` 永不成立，表现为进度**永远差一截**（#44）。凡是「从 N 个里挑 K 个」的模型，一律显式区分 `total` 与 `needed` |
| R38 | **不要写「查不到就静默返回空」的函数**：`bundleProgress(id)` 传入对象时返回 `[]` 而非报错，于是「界面已勾选、进度为 0」两个真相并存且不抛异常（#45）。查询类函数要么**同时兼容两种入参**，要么**显式失败**；空数组必须是"确实没有"，不能是"参数用错了" |
| R39 | **排查状态矛盾时，一条日志只取一个时点**：把不同时刻的值拼进同一句日志，会造出根本不存在的"幽灵 bug"，白烧好几轮（#46）。**更好的做法是写最小复现脚本**：把可疑函数单独跑一遍（本项目 6 行就定位到真因），比在被测系统里加日志快得多 |
| R40 | **别用文本工具整文件重写 HTML**：为回退版本号用 `WriteAllText` 重写 `index.html` 时带上了 UTF-8 BOM，随后被提交，导致**本地与线上哈希不一致**（仅差 3 字节 BOM，排查时极易误判成"部署没生效"）。改 HTML **优先用定点替换**（`edit`）而非整文件重写；确需重写则显式使用**不带 BOM** 的 `UTF8Encoding($false)` |
| R41 | **URL 同步要区分「用户导航」与「代码顺带」**：模块切换用 `replaceState`（就地改写，不压历史），只有「打开条目详情」用 `pushState`（可回退的最小粒度）；程序化写 hash 期间置 `routerGuard`，防止自己触发的 `hashchange` 再跑一遍（#47）。**判据**：如果用户按一次后退没回到"上一个有意义的位置"，就是写 hash 的粒度错了 |
| R42 | **规则要连适用边界一起记**：R18「跳转前重置筛选」只适用于**跨模块**跳转（目标可能落在当前筛选之外）；套用到同模块内切换条目，会把用户已选的筛选条件无谓清空（#48）。引用既有规则时先确认它的前提在当前场景是否成立 |
| R43 | **卡片内嵌的可交互元素必须显式拦截冒泡，并排在整卡判断之前**：礼物 chip、收集包勾选框都是卡片内部的小控件，委托里若先匹配 `[data-id]`，点小控件会变成"打开卡片本身"（#49）。**顺序 + `stopPropagation` 两件都要做** |
| R44 | **区分「数据错」与「内容还没做」**：礼物的 50 个不可点项里只有 2 个是真正的占位说明，其余 48 个属于尚未收录的模块（#50）。统计类排查先分类再下结论，否则会把正常的内容进度当成缺陷去"修数据" |
| R45 | **chip / 标签类元素禁止词内断行**：窄容器里会出现「巧克力／蛋糕」这种拆行（#51）。`white-space: nowrap` 只禁止**词内**断行，容器之间的换行照常，不影响布局 |
| R46 | **解析模板一律忽略大小写**：同一模板在同一页面内会混用 `{{Name}}` 与 `{{name}}`，区分大小写会静默漏掉整批数据（#52 实测漏了 15/81 道菜的配料）。**"解析出来是空的"优先怀疑匹配规则，而不是怀疑源数据缺失** |
| R47 | **id 要从权威源派生，不要从译名派生**：中文名 slug 化会得到空串（#53），而 id 往往还要兼作贴图/文件名。用 infobox 的 `image`（英文文件名）生成 id，可与上游命名天然对齐 |
| R48 | **验证页必须与真实页面处于同一路径上下文**：把页面复制到别处再加载，相对路径会静默失效，于是把"环境问题"看成"产品 bug"（#55，为此白查了一个不存在的严重缺陷）。**截图验证一律用站点真实文件/真实 URL**；确需临时副本时，所有相对资源都要显式改绝对路径（含 JS 里拼出来的路径） |
| R49 | **重构要盘清「同一模式的全部出现点」，漏一处等于没重构**：P0 收敛了 5 处模块硬编码，却漏了第 6 处 `NAME_INDEX`，加模块后立刻表现为"新模块内容无法被跳转"（#56）。**判据**：完成重构后，新增一个模块/条目，看它是否自动获得全部既有能力 |
| R50 | **手工早期数据要用权威源复检「命名」而不只是「存在性」**：`verify-wiki.js` 只回答"条目是否存在"，「名字是否是当前正式译名」它管不到（#57 查出 4 个过时译名）。批量命名核对一律对照 `Module:Items` 名表 |
| R51 | **解析 Wiki 表格必须实现完整的单元格语义**：`\|` 开头 = 新单元格（**含空单元格**）、不带竖线 = 续行、`!` = 表头、`colspan` 要展开、单元格内换行要先归一（#58~#65）。**按行朴素切分一定会在某一类数据上静默丢字段** |
| R52 | **解析器必须配「零问题」收口断言**：解析完先自报 `无材料 0 / 无来源 0 / id 唯一`，不为 0 就不许往数据里写（#60/#63 都是这一条拦下来的）。**"其余看着都对"不构成数据可用的理由** |
| R53 | **新增模块的 id 要与全站既有 id 对撞检查**：id 是深链接键，跨模块必须唯一（#66 的 `iron-bar`/`gold-bar`）。冲突时**以已有模块为准**，新数据让步——已上线链接的稳定性优先于新数据完整性 |
| R54 | **同一模板在不同列可能承担不同语义**：机器产品表里「原料」与「食用增益」都用 `{{Name\|...}}`，按模板形态全量提取会把增益当原料（#68）。**字段提取要结合所在列/位置，不能只看模板写法** |
| R55 | **「没有固定值」不等于「没有信息」**：变价品（果酒/果干/熏鱼…）没有固定售价，但都有明确计价规则（#69）。数据里必须把规则一起存下来，界面才有东西可展示——否则用户只看到一句「浮动」，等于没写 |
| R56 | **给机器读的输出一律用 ASCII 标记**：`✓/✗` 在本机终端被编码弄乱后 `Select-String` 一条都搜不到，**会直接导致"看不见失败"**（#70）。自检日志统一用 `[OK]/[FAIL]/[INFO]`，任何管道与终端都能安全检索 |
| R57 | **进度/勾选用「物品名」作键时，必须先保证名字唯一**：古物两件颜色变体同名，勾一件等于勾两件（#72），而**界面完全看不出异常**。凡以名字为键的 store，都要配一条「清单无重名」断言 |
| R58 | **数字对不上时先做逐条差集，不要先改解析器**：分类 43 项 vs 解析 42 条，差的是「同一古物的两个颜色变体」这一可解释原因（#71）。**先证明差异可解释，再决定动不动代码** |
| R59 | **文件名永远从数据源里读，不要推导**（R13 的再确认）：`Strange Doll (green).png` 带括号且颜色小写，任何「首字母大写 + 下划线」的推导规则都会失败（#74）。解析 wikitext 时把 `[[File:...]]` 原样存下来，比事后猜名字可靠得多 |
| R60 | **文档里的数字是"数据"，不是"介绍文字"**：`README.md` 一度与现状脱节 8 处（#75），而接手者会照着它做判断。**任何写进文档的数字，都要能从一条命令的输出里核对**（本项目统一从 `node test/check.js` 的 `[INFO]/[OK]` 行读，分组数之类回数据源数）；每轮改完顺手核对一次，**README 与 PROBLEMS.md 要跟代码一起改** |
| R61 | **居中 + 可能溢出，就不要用 `justify-content: center`**：溢出时居中会把起始侧内容推到滚动区之外，那部分**再也滚不到**（#76）。改用首尾 `margin: auto`——有剩余空间才均分，溢出时自动塌成 0。**导航/标签条一律按"单行 + 横向滚动"设计**，不要用折行（折行会顶掉内容区高度，且"谁掉到第二行"取决于视口宽度） |
| R62 | **布局 API 也要判存**（R2 的延伸）：`check.js` 的 DOM 模拟没有布局引擎，`getBoundingClientRect` / `offsetWidth` 之类**不存在**（#77）。新增这类调用前先 `typeof x.getBoundingClientRect !== "function"` 判存，否则自检直接抛错。**判据**：写完后必须跑一次 `node test/check.js`，不能只看浏览器里正常 |
| R63 | **验证指标优先选"结构量"，避开"内容量"**：墨迹占比、关键词命中这类**内容相关**的指标会随内容本身变化（第二行只放一个条目，占比就低于阈值，折行被判成单行，见 #78）；几何尺寸、计数这类**结构量**才稳定。**判据**：如果你的度量阈值需要"根据这次的数据"来调，那就是选错了指标 |
| R64 | **修完症状要回头看"是谁把它造出来的"**：R40 记录了 BOM 导致本地/线上哈希不一致，处置却是"手动删掉 `index.html` 的 BOM"——源头 `deploy.ps1` 的 `WriteAllText(..., UTF8Encoding($true))` 一字未改，于是**每轮部署复发一次**，持续到第十四轮才被发现（#79）。**判据**：一条问题记录若只改了"产物"、没改"生产这个产物的那段代码/流程"，它就一定会按固定节奏复发——**修完记得问一句"下一个人还会再撞上吗"** |
| R65 | **"被遮住的元素"要问一句"它下面透出来了吗"**：贴图带 alpha 通道时，「把兜底压在贴图下层」**不等于**「看不见兜底」——每个透明像素都是兜底的一扇窗（#80：平均 48.5% 的格子面积在透出，而肉眼只觉得"有点脏"）。**判据**：凡靠层叠/遮盖来隐藏元素的地方，都要用 **A/B 截图或 alpha 覆盖率**实测一次。配套两条：①**显隐开关要由"失败事件"（`onerror`）驱动，不要由"成功事件"（`onload`）驱动**——后者在缓存命中时可能不触发；②层叠之外的判据要用**显式类名**（`.has-img`）而不是 `:has()`/结构推断，纯 emoji 图标这类"没有贴图、兜底即内容"的变体才不会被误伤 |
| R66 | **比对线上/本地文件必须先归一化行尾**：本机 `core.autocrlf=true`，而 `git checkout` 会把工作区写成 CRLF、仓库与线上是 LF，直接比字节会报出「本地大 N 字节」的假不一致，**而 N 恰好等于行数**（#81）。**判据**：差值与行数相等时先怀疑行尾，不要怀疑内容。核验脚本除了哈希，还应加**内容断言**（关键行是否真在线上）——因为哈希一致也可能只是"比错了对象" |
| R67 | **审计工具要核对的"目标集合"必须自动发现，不能硬编码**（R25/R49 的延伸）：`verify-wiki.js` 的模块清单写死 7 个，导致此后新增的 **355 条从未被存在性核对**（#82）——**规则写进了文档，工具却停在原地**。判据：工具的覆盖数应当随数据自动增长；如果它报出的条数**明显小于**站点条数，那就是覆盖盲区，不是"数据少" |
| R68 | **量行数/字节数用 .NET 读，不要用 `Get-Content` 的 `.Count`**：本机 PowerShell 对无 BOM 的 UTF-8 文件按 ANSI 解码，行数会失真（#83 实测 113 vs 170），足以让人误判"文件被截断"。**判据**：文件大小与行数对不上时，**先换一把尺子复量**，再怀疑文件——与 #81 同一个道理：先怀疑度量口径 |
| R69 | **工作区有未提交的真实改动时，绝不用 `git checkout` / `git restore` 去"清理临时改动"**：排查 #80 时我在同一个文件上既有真实修复、又有临时注入，用 `git checkout -- css/style.css` 清注入，**把尚未提交的真实修复一起回退了**（该文件当时没有提交点可回退到）。正确做法二选一：①**先把真实改动落盘**（提交或备份一份）再做实验；②把临时注入写在**独立的、不进版本控制的文件**里（例如另存一份样式表），不要往真实文件里塞。**判据**：只要分不清"这次回退会掉什么"，就不要回退——先 `git diff` 看清楚 |
| R70 | **跨模块的"同一件东西"要让两边对得上，并配交叉校验断言**：果树模块的每个树苗都必须能在种子模块找到，且**两边对同一树苗的售价必须一致**（#84）——这类一致性光看界面发现不了，只能靠断言。**判据**：新增模块若与已有模块描述同一个对象，就写一条「A 的每个 X 都能在 B 里找到 + 关键字段相等」的断言，而不是人工核对一遍 |
| R71 | **"同物多名"用别名，且别名不得覆盖正式名**：果树条目以树为名（与 Wiki 分类一致），果实名走 `aka` 别名，这样种子的「成熟后得到 苹果」与 NPC 礼物「桃子」都能命中（#84）。**纪律**：别名一律**后置、不覆盖**（`if (!map.has(a))`），冲突时以已有模块为准（R53）——「芒果」已由农作物收录，果树模块就**不登记**该别名，并加断言守住 |
| R72 | **解析兜底值必须本身可被数据源验证**：「绿雨树」没有 infobox，我从正文里取**第一个能在种子模块中找到的链接**作为种子（#86）。这条规则之所以成立，是因为棕榈树的正文里只有「椰子」（不在种子模块），于是它**正确地**解析为"没有种子"——**如果兜底规则是"取正文第一个链接"，就会硬塞给它一个错的种子**。**判据**：兜底不能只看"能不能取到值"，要看"取到的值能不能被另一个数据源确认" |
| R73 | **中文不要按字数截断**：卡片说明用 `.slice(0, 22) + "…"` 会切在词中间，出现「…由长满苔藓的种子种」这种断词（#87）。要截就按**行**（CSS `line-clamp`），或者干脆不截、把全文留在详情页。**判据**：截断位置对中文没有语义边界，按字符数截必然出错 |
| R74 | **响应式断点不要贴着"刚好差一点"的宽度取**：1024px 处可用内宽 745px，而 3 列需要 748px——**差 3px 掉一整档**（#88）。断点要取在"两边都稳定"的位置（本项目定在 1120）。**判据**：定完断点后在**断点两侧各 ±1px** 各截一张图对比，跳档了就是取错了 |
| R75 | **媒体查询叠加时，每条都要问"上面那条改了什么，我要不要还回去"**：`≤1120` 隐藏了 `.nav-label`，`≤640` 只切回横排却没还原名称，手机端于是变成一条"只有图标"的导航（#89）。**判据**：写窄屏规则时，把宽屏规则里所有 `display:none` 过一次，逐个确认是否需要还原 |
| R76 | **凡是靠"周期对齐"的视觉，周期必须同源，且要有断言锁住**：木板缝写 46px、行距是 44px，两个周期各写各的，越往下越错位（#91）。**要求**：① 周期只在一处定义（或用同一个值派生）；② 加一条**源码级**断言校验"缝周期 == 条目高 + 间距"——这类几何关系在 DOM 模拟里量不到，但对 CSS 源码做一致性校验可行，且正是它防住了回归 |
| R77 | **可滚动容器的背景若要跟内容对齐，必须 `background-attachment: local`**：背景默认贴盒子、不随内容滚动，一滚就错位（#94）。且 `local` 必须写在 `background` **简写之后**，否则被重置回 `scroll` |
| R78 | **纵向 flex 容器里，"高度参与对齐"的子项一律要 `flex: 0 0 auto`**：内容溢出时子项默认被压缩，标题从 28px 缩到 18px、把下面 17 个条目整体顶偏 10px（#93）。**判据**：容器里只要有一个子项写了 `flex: 0 0 auto`，就把其余**所有**定高的子项过一遍 |
| R79 | **sticky 元素的粘附范围是它的父容器**：父容器没包住的部分（页脚）会成为永远露白的区域（#92）。**判据**：做 sticky 布局时先问"父容器是否一直延伸到我想粘附的边界" |
| R80 | **"按周期/步长对齐"的校验，比较双方必须在同一坐标系**：用视口坐标比内容坐标，滚动量不是周期的整数倍就会误报错位（#95，与 #90 同属**口径错**）。**判据**：写这类断言前先明确"我在谁的坐标系里"，并把换算写进注释 |
| R81 | **同一实体在 Wiki 上"查不到"时，先确认它是不是另一个实体的一部分**：`Big Coop`/`Deluxe Barn` 没有独立页面，只是 `鸡舍`/`畜棚` 页里的升级档，`langlinks` 因此取不到（#98）。**做法**：去父页面里找结构化的对照表，**按列配对**抽取，而不是手写一份映射（手写的没法验证，源头变了也不会被发现） |
| R82 | **英文名解析要跟着重定向走，并对结果去重**：`Brown Egg` 重定向到 `Egg`，即两者是同一件物品；不跟重定向就会既拿不到中文名、又产生重复项（#99）。**判据**：解析结果里"像是重复"的东西，先去源头确认它是不是别名 |
| R83 | **像素素材若原图大于目标格，先做整数倍缩放再入库**：直接交给 CSS 会算出 0.533 这类非整数比，像素画必糊（#97，R23 的前提）。**要求**：缩放脚本必须打印「原尺寸 → 缩放比 → 新尺寸」，否则"把图缩成 1×1"这种事故只能靠肉眼发现 |
| R84 | **数值与说明要分开存，不要用一个字段硬塞两种含义**：`sellprice` 可能是数字、`N/A` 或一条公式（#101）。**做法**：数值进 `sell`、说明进 `sellText`，渲染时二选一，并断言「两者必居其一」。**判据**：解析一个字段前先问「它的取值是不是只有一种形态」，若不止一种，就该拆字段 |

## 二·补充、解决方案与规避总纲（三层防线）

### ① 自动化工具层（机器把关，无需记忆）

| 工具 | 作用 | 拦截的问题 |

```
改数据/代码 → node test/check.js → （新增数据时）node test/verify-wiki.js
→ 双击 deploy.bat（自动：bump 版本 → 自检 → 下载贴图 → 推送 → Actions 部署）
→ 线上核对（gh api runs / Node fetch 抽查）
```

### ③ 经验规则层

见下表 **R1~R64**，核心六条：
- **R12 新增数据先验证存在性**（用 verify-wiki.js / Wiki 搜索，杜绝编造）
- **R13 / R59 文件名不手工猜**（用 `pageimages` API 按英文条目名取真实 URL；文件名永远从数据源读）
- **R15 能用 Node fetch 直连外部源就自己做**（本项目沙箱中 Node fetch 可通 Wiki，而 PowerShell 的 `Invoke-WebRequest` 报「基础连接已经关闭」——**该限制来自沙箱，不是 schannel**，#24 已证伪原判断）
- **R51 / R52 解析 Wiki 表格要实现完整单元格语义，并配「零问题」收口断言**（#58~#65 连踩 13 版）
- **R56 给机器读的输出一律用 ASCII 标记**（`✓/✗` 被终端编码弄乱后 `Select-String` 一条都搜不到 = 看不见失败）
- **R60 文档里的数字也是数据**（README 一度脱节 8 处，接手者会照着错的做判断）
