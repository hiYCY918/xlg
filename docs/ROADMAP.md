### 1.3 根因修复：给文档数字加断言（**这一步才是重点**）

**实测**：`test/check.js` 里搜 `README|PROBLEMS|.md|footer|页脚` → **完全没有匹配**。

也就是说 **R60 是一条"没有执行手段的规则"**。这和 R97 说的是同一种病：

> 有断言的缺口表会自己喊缺什么，没断言的只会沉默。

**要加的断言**（建议放 check.js 新增一节「文档自一致性」）：

```js
/* R60：文档里的数字是数据。这里只查"能机器核对"的那几类——
 * 模块数、条目数、贴图数、断言数。措辞千变万化，所以用正则抓"数字+量词"。 */
const readme = fs.readFileSync(path.join(__dirname, "..", "README.md"), "utf8");
const real = { modules: data.REGISTRY.length, items: /* 全部模块条目之和 */, imgs: /* img/*.png 数 */ };

/* ① 模块列表那行：数量必须等于模块数，且**不得有重复项**（这条直接抓「树木出现两次」） */
const listLine = readme.split("\n").find((l) => l.includes("农作物") && l.includes("收集物"));
const names = listLine.split("·").map((s) => s.trim().replace(/^\S+\s*/, "")).filter(Boolean);
log(names.length === real.modules, "README 模块列表数量 == 模块数（" + names.length + "/" + real.modules + "）");
const dup = names.filter((v, i) => names.indexOf(v) !== i);
log(dup.length === 0, "README 模块列表无重复项" + (dup.length ? "：" + dup.join(",") : ""));

/* ② 全文抓「N 个模块 / N 大模块 / N 模块」，逐个比对 */
/* ③ 抓「全 N 条」比对条目数；④ 抓「N 张」比对贴图数 */
```

## 四、阶段 2：CI 加 test（让防线真正生效）

### 问题

`.github/workflows/pages.yml` 现在只有 4 步：

```
Checkout → Setup Pages → Upload artifact → Deploy to GitHub Pages
```

**没有 test**。而本地 `scripts/deploy.ps1:71-75` **是有闸门的**（跑 `check.js`，失败即中止部署）。

所以：**防线只在本地那条路上存在**。任何人（包括自己）直接 `git push` 就跳过了全部 307 处断言。

### 要改的

`.github/workflows/pages.yml`：加一个 `test` job，让 `deploy` 依赖它。

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20" }
      - name: 全量自检
        run: node test/check.js

  deploy:
    needs: test          # ← 关键：测试不过就不部署
    environment: ...
```

### 三个注意点

1. **`check.js` 是离线的**（用自制 DOM 模拟），可以放心跑 ✓
2. **`verify-wiki.js` / `audit-completeness.js` 需要联网** —— 不要放进阻塞链。可选：加一个 `continue-on-error: true` 的独立 job 做**报告**，或先不加
3. **`upload-pages-artifact` 的 `path: "."` 会把整个仓库发布出去**（含 `test/` `scripts/` `docs/`）。这是现状、不是新问题，但既然要动这个文件，**顺手改成只发布站点文件**（复制到 `dist/` 再 upload）更干净

### 完成标准

- 故意提交一个会让 `check.js` 失败的改动 → GitHub Actions **红灯且不部署**
- 恢复后 → 绿灯、正常部署

### 不要做

- ❌ 不要在 CI 里跑 `deploy.ps1`（那是 Windows PowerShell，CI 是 ubuntu）
- ❌ 不要因为"本地已经跑过了"就跳过这一步——这条的价值恰恰在于**它不依赖任何人自觉**

## 五、阶段 3：SEO 基础设施（拿流量）

### 3a. 低成本部分（当天可完成）

**实测现状：全部为空。**

| 项 | 现状 | 要做 |
|---|---|---|
| favicon | `index.html` 无 `<link rel="icon">`，`favicon.ico` 不存在 | 从 `img/npc-junimo.png`（48×48）生成 32×32 + 180×180，加 `<link rel="icon">` / `apple-touch-icon` |
| `robots.txt` | 不存在 | 允许全站 + 指向 sitemap |
| `sitemap.xml` | 不存在 | 先只列首页（单页站，价值有限但要有） |
| OG / Twitter Card | 不存在 | `og:title` / `og:description` / `og:image` / `og:url` / `twitter:card` —— **分享到微信/QQ 才有卡片预览** |
| canonical | 不存在 | 指向上线地址 |
| 结构化数据 | 不存在 | `WebSite`（可选再加 `Dataset`） |

**注意**：`index.html` 改完要确认**没有 BOM**（R40——历史上有一次就是被这个坑到，本地与线上哈希差 3 字节）。

### 3b. 预渲染决策（**需要你先拍板，不要直接开工**）

**核心矛盾**：单页 + hash 路由 → **搜索引擎只索引首页**，964 条内容全部拿不到长尾流量。这是攻略站价值的 80%。

三个方案：

| 方案 | 做法 | 收益 | 成本 / 风险 |
|---|---|---|---|
| **A** | 按**条目**预渲染 964 个 HTML | 最大（"传说之鱼怎么钓"能直接命中） | 高：要抽渲染逻辑或做静态快照；每次改数据要重新生成 964 个文件 |
| **B**（推荐） | 只按**模块**预渲染 23 个页面（`/fish/index.html`） | 中（"星露谷钓鱼攻略"能命中） | 中：23 个文件好维护；条目仍走 hash |
| **C** | 维持单页，只做 3a | 低 | 低 |

**无论选哪个，都必须先解决一件事：旧链接兼容。**

现在已经分享出去的深链接形如 `#fishing/legend`（**原文写的是 `#fish/legend`，那是错的**：钓鱼模块的 id 是 `fishing`，`fish` 会静默降级回默认模块。第三十轮已改正，并加了断言守住——文档里任何 `#模块/条目` 示例都必须真的能落地）。改成 `/fishing/legend.html` 之后**这些链接全部失效**。要决定：

- 保留 hash 路由**同时**提供静态页（双轨，JS 在静态页里接管）
- 或接受断链，在页面里加一个"链接已更新"的跳转层
- 或只做模块级（方案 B）——`#fishing` 这种粗粒度链接失效影响较小

**实验已完成（第三十轮，见 `test/prerender-probe.js`）**，实测数字推翻了本节原来的一个隐含前提：

| 实测项 | 数字 | 对方案的影响 |
|---|---|---|
| 整页快照 | **982 KB/页**（其中 `#page` 969.9 KB，含**全部 964 条**的内容；侧栏仅 7.8 KB） | 964 页 ≈ **924 MB**，naive 快照**不可行** |
| 23 个模块整页快照 | ≈ **22 MB** | 方案 B 照原设想做也很重 |
| 只取详情片段 | **1.5~2.6 KB/条** | 964 条 ≈ **1.4 MB**，体积完全可行 |
| 站内链接 | 渲染结果里 `<a href>` = **0 个**，564 处全是 `data-goto-*` 交给 JS 委托 | **静态快照没有可爬的链接图**，必须改渲染层发真 href |
| 快照正文 | 剥掉 `<script>` 后中文正文仍在 | 爬虫确实能读到内容 ✓ |

**结论**：成本不在"存 HTML"，而在**渲染层改造**（发真 `<a href>` + 能只产出"一条详情"的薄页面）。
好消息是 `test/check.js` 已有一套自制 DOM 模拟，能在 Node 里直接调 `DETAIL_RENDERERS` 拿 HTML——
生成器不必依赖 headless Chrome，方案 A 的边际成本比原文估的低。

- `robots.txt` / `sitemap.xml` 可访问

## 六、阶段 4：进度导出导入（留人）

### 问题

收集包与博物馆勾选是这个站**最有黏性**的功能，但数据只在浏览器里。

**实测**：`js/main.js` 里 `export` / `import` / `download` / `导出` / `导入` **各 0 处命中**。

**两个键名**（`js/main.js` 里有常量，别硬编码字符串）：

| 键 | 行号 | 内容 |
|---|---|---|
| `xlg.bundleProgress.v1` | `main.js:529` | 收集包进度 |
| `xlg.museum.v1` | `main.js:1343` | 博物馆捐赠 |

### 要做

1. **导出文件格式**（带版本号，便于将来演进）：

```json
{ "version": 1, "exportedAt": "2026-10-09T22:00:00+08:00", "bundle": { ... }, "museum": { ... } }
```

2. **导出**：下载 `.json` **和** 复制到剪贴板（双通道——手机上复制粘贴比下载文件顺手）
3. **导入**：文件选择 **和** 粘贴文本框；**必须校验结构**，非法输入不能崩（R2 空值安全）
4. **合并策略要先定**：并集（保留两边已勾选的）还是覆盖？**建议并集**，并在确认框里说明
5. **UI 位置**：收集包与古物模块的工具栏（`chipBar` / `controlRow` 那一带），不要放进弹窗

### 断言（check.js）

- **round-trip 一致性**：导出 → 导入 → 进度数组逐字节相同
- **非法输入不抛异常**：空字符串 / 非 JSON / 缺字段 / 版本号不匹配 → 都走"提示并保持原状"
- **导入不污染**：失败时 localStorage 不被改动

### 不要做

- ❌ 不要顺手做"云同步"或"账号"（那会把纯静态站变成需要后端的项目，性质变了）
- ❌ 不要改现有的键名（会和用户已有进度对不上）
